# Repository Rules & Guidelines

## 1. Simple and Professional Terminology

- **Use Plain, Industry-Standard Terms**:
  - Favor clear, standard terms across the entire codebase (e.g., `build`, `run`, `verify`, `cleanup`, `process`, `service`, `port`, `stop`, `retry`).
  - Avoid obscure jargon, gimmicks, or overly abstract metaphors.
- **Clear & Professional Naming**:
  - Variable, function, interface, type, package, and file names must be descriptive, intuitive, and professional.
  - CLI flags, terminal messages, and logs must be plain, readable, and direct.
- **Actionable Error Messages**:
  - Errors must describe what failed, why it failed, and what action the developer or agent can take.

## 2. Git & Release Discipline

- Never commit, push, create branches, or execute git operations without explicit user permission (`RULE[user_global]`).
